# Phase 12.1 Step C: User Inbox & Notification Preference API Contracts

## 1. Overview & Architectural Boundaries

Phase 12.1 Step C implements the client-facing REST APIs for reading and acknowledging in-app notifications (`inbox_messages`) and managing notification preferences (`notification_preferences`).

### Cardinal Governance Boundaries
1. **Decision #54 (NO WRITES ON GET):** `GET /api/me/inbox` is strictly read-only. It must never mutate database state, mark messages as read, or upsert records during query execution.
2. **Strict Ownership Isolation:** All mutations and queries are scoped to the authenticated caller (`req.user.id`). Attempting to mutate or read another user's inbox message returns `404 Not Found` (preventing ID enumeration).
3. **Preference Record Preservation:** Unsubscribe operations update `emailEnabled = false` on the existing `notification_preferences` record. Records are never deleted upon unsubscription.

---

## 2. API Endpoint Specifications

### 2.1 `GET /api/me/inbox`
Retrieves a paginated list of inbox notifications for the authenticated user.

- **Method:** `GET`
- **Path:** `/api/me/inbox`
- **Authentication:** `requireAuth`
- **Query Parameters:**
  - `poolId` (optional, UUID): Filter messages for a specific pool.
  - `unreadOnly` (optional, boolean, default `false`): If `true`, returns only messages where `readAt IS NULL`.
  - `limit` (optional, integer, default `50`, max `100`): Maximum number of messages to return.
  - `offset` (optional, integer, default `0`): Pagination offset.
- **Side Effects:** None (Decision #54 compliant).
- **Responses:**
  - `200 OK`:
    ```json
    {
      "messages": [
        {
          "id": "c1f7a0c0-6b6f-4f7f-8e4a-5f3a7c6f0001",
          "poolId": "d2f7a0c0-6b6f-4f7f-8e4a-5f3a7c6f0002",
          "type": "PICK_REMINDER",
          "payload": {
            "weekNumber": 4,
            "deadline": "2026-10-04T17:00:00.000Z",
            "hoursRemaining": 24
          },
          "dedupeKey": "reminder-d2f7...-24h",
          "readAt": null,
          "createdAt": "2026-10-03T17:00:00.000Z"
        }
      ],
      "totalCount": 12,
      "unreadCount": 3
    }
    ```
  - `401 Unauthorized`: Caller is not authenticated.

### 2.2 `POST /api/me/inbox/:id/read`
Marks a single inbox notification as read.

- **Method:** `POST`
- **Path:** `/api/me/inbox/:id/read`
- **Authentication:** `requireAuth`
- **URL Parameters:**
  - `id` (UUID): ID of the inbox message.
- **Authorization & Scoping:**
  - Must verify `userId = req.user.id`.
  - If no matching message exists for `req.user.id`, returns `404 Not Found`.
- **Behavior:**
  - Idempotent: If `readAt` is already set, retains the original timestamp and returns 200.
  - If `readAt` is null, sets `readAt = NOW()`.
- **Responses:**
  - `200 OK`:
    ```json
    {
      "success": true,
      "message": {
        "id": "c1f7a0c0-6b6f-4f7f-8e4a-5f3a7c6f0001",
        "readAt": "2026-10-02T20:15:00.000Z"
      }
    }
    ```
  - `404 Not Found`: Message not found or not owned by the caller.

---

### 2.3 `POST /api/me/inbox/read-all`
Marks all unread inbox notifications as read for the authenticated user.

- **Method:** `POST`
- **Path:** `/api/me/inbox/read-all`
- **Authentication:** `requireAuth`
- **Request Body (JSON):**
  - `poolId` (optional, UUID): Scope bulk read operation to a specific pool.
- **Behavior:**
  - Executes `UPDATE inbox_messages SET read_at = NOW() WHERE user_id = $1 AND read_at IS NULL [AND pool_id = $2]`.
- **Responses:**
  - `200 OK`:
    ```json
    {
      "success": true,
      "markedReadCount": 3
    }
    ```
  - `401 Unauthorized`: Caller is not authenticated.

---

### 2.4 `PUT /api/me/notification-prefs`
Updates or creates the user's notification preferences.

- **Method:** `PUT`
- **Path:** `/api/me/notification-prefs`
- **Authentication:** `requireAuth`
- **Request Body (JSON):**
  - `emailEnabled` (optional, boolean): Global email opt-in/opt-out flag.
  - `reminderOffsetsHours` (optional, array of integers): Array of hour offsets before game lock (e.g. `[24, 2]`).
- **Validation Rules:**
  - `reminderOffsetsHours` must contain between 1 and 5 elements (inclusive).
  - Each value in `reminderOffsetsHours` must be an integer between 1 and 168 (inclusive).
  - Rejects null elements or empty arrays if provided.
- **Behavior:**
  - Upserts `notification_preferences` for `userId = req.user.id`.
  - Automatically generates `unsubscribeToken` UUID if creating a new record.
- **Responses:**
  - `200 OK`:
    ```json
    {
      "userId": "a1f7a0c0-6b6f-4f7f-8e4a-5f3a7c6f0001",
      "emailEnabled": false,
      "reminderOffsetsHours": [24, 2],
      "updatedAt": "2026-10-02T20:15:00.000Z"
    }
    ```
  - `400 Bad Request`: Validation failure on `reminderOffsetsHours`.
  - `401 Unauthorized`: Caller is not authenticated.

### 2.5 Unsubscribe Handling (Token-Based & Preference-Preserving)
Provides direct unsubscribe links in outbound emails without requiring prior user login.

- **Method:** `GET` / `POST`
- **Path:** `/api/notifications/unsubscribe`
- **Authentication:** None (secured by secret `unsubscribeToken` UUID).
- **Parameters / Payload:**
  - `token` (UUID, query parameter or body).
- **Behavior:**
  - Looks up `notification_preferences` by `unsubscribeToken`.
  - If found:
    - Sets `emailEnabled = false`.
    - Updates `updatedAt = NOW()`.
    - **CRITICAL:** Retains the `notification_preferences` row and does NOT delete user settings or tokens.
  - If not found:
    - Returns `404 Not Found` with a safe error message.
- **Responses:**
  - `200 OK`:
    ```json
    {
      "success": true,
      "message": "Successfully unsubscribed from email notifications."
    }
    ```
  - `400 Bad Request`: Missing or invalid UUID token format.
  - `404 Not Found`: Invalid or expired unsubscribe token.
