### 3.4 Root Cause Analysis
The previous test run contacted the hosted database because:
1. `src/services/weeklyWrapUp.ts` imported the default `prisma` singleton from `src/db/client.ts`.
2. `src/db/client.ts` initialized `new PrismaClient()` from `process.env.DATABASE_URL` without calling `assertDisposableDatabase()` or checking host isolation.
3. The root `.env` file contained the Supabase session pooler connection string.
4. When `vitest` executed `runWeeklyWrapUp`, it used the singleton client connecting directly to Supabase.
5. **Remediation:** Decision #32 flipped `.env` to `localhost:5432/pickem_rehearsal`, moved hosted credentials to `.env.hosted`, and integrated `assertDisposableUrl()` into Vitest `setupFiles`.
