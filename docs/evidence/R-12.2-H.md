## 2. BR-5 Authorization Hardening (S-4 / S-2 Fix)

### Implemented Middlewares in `src/middleware/auth.ts`
1. **`requirePoolCommissioner`**:
   - Validates that `:pool_id` (or body/query `pool_id`) is a valid UUID format (400 if malformed).
   - Confirms the target pool exists in the database (404 if not found).
   - Enforces that `pool.adminId === req.user.id` or `req.user.role === Role.ADMIN` (403 if forbidden).
2. **`requirePoolMember`**:
   - Validates that `:pool_id` (or body/query `pool_id`) is a valid UUID format (400 if malformed).
   - Confirms the target pool exists in the database (404 if not found).
   - Automatically permits the pool commissioner (`pool.adminId === req.user.id`) or global `Role.ADMIN`.
   - For regular users, verifies an active membership record in `pool_memberships` where `status = 'ACTIVE'` (403 if not an active member).

## 3. BR-4 Money Math & BR-4b Idempotency

### Refactored Split Calculation (`src/services/weeklyWrapUp.ts`)
- **Pure `Prisma.Decimal` Math:** All operations (`dividedBy`, `toDecimalPlaces(2, ROUND_HALF_UP)`) execute entirely using `Prisma.Decimal` instances.
- **Zero-Value Suppression:** If calculated penalty share evaluates to `0.00` (or non-positive), the write loop is bypassed, preserving ledger immutability and sign invariants.
- **Claim Table Idempotency Guard:** `tx.weekly_wrapups.createMany({ data: [{ poolId, weekNumber: weekNo }], skipDuplicates: true })` check executes at the absolute beginning of the transaction. If `count === 0`, execution halts and returns `{ applied: false, reason: 'ALREADY_WRAPPED_UP' }`.

### Evaluated Split Examples
- **10.00 split 3 ways:** `new Prisma.Decimal('10.00').dividedBy(3).toDecimalPlaces(2)` = `3.33` per member.
- **1.00 split 3 ways:** `new Prisma.Decimal('1.00').dividedBy(3).toDecimalPlaces(2)` = `0.33` per member.
- **0.02 split 3 ways:** `new Prisma.Decimal('0.02').dividedBy(3).toDecimalPlaces(2)` = `0.01` per member.
